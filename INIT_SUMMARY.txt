PROJEKT-NAME: optik
BESCHREIBUNG: Hochperformantes Kamera-Management-System
TECHNOLOGIE:  Python 3.10+ + Rust/Maturin + NNG
LIZENZ:       Apache 2.0 (kostenlos, kommerzielle Nutzung erlaubt)
VERSION:      0.1.0

================================================================================
                            KERNFEATURES
================================================================================

✅ Multi-Vendor Support      Basler (pypylon) + IDS (ids_peak)
✅ Hybride Architektur       Python API + Rust/Maturin Core
✅ Netzwerk-Multiplexer      CBOR über NNG, ein Port für alle Kameras
✅ Einheitliche API          Exposure, Gain, PixelFormat, Trigger
✅ Thread-Safe               Sichere nebenläufige Zugriffe
✅ CLI + Python API          Fire-basierte Kommandozeile
✅ Tests                     pytest mit Mocks (ohne echte Hardware)
✅ Konfiguration             TOML-basiert
✅ Dokumentation             README, QUICKSTART, DEVELOPMENT

================================================================================
                          QUICK START
================================================================================

1. SETUP:
   cd /Users/anton.feldmann/Projects/priv/optik
   ./setup.sh

2. KAMERAS AUFLISTEN:
   optik list

3. FRAME GRABBEN:
   optik grab --camera 0 --output frame.png

4. MUX-SERVER STARTEN:
   optik mux-server --port 5555

5. PYTHON API:
   from optik import MultiController
   
   with MultiController() as ctrl:
       cameras = ctrl.discover()
       frame = cameras[0].safe_get_image()

================================================================================
                          ARCHITEKTUR HIGHLIGHTS
================================================================================

1. CAMERA ABSTRACTION:
   - Abstrakte Basis-Klasse mit gemeinsamer Schnittstelle
   - Vendor-spezifische Implementierungen (Basler, IDS)
   - Thread-safe Frame Grabbing mit safe_get_image()

2. DISCOVERY PATTERN:
   - Vendor-spezifische Controller
   - MultiController für Multi-Vendor Support
   - DeviceInfo für Kamera-Metadaten

3. MULTIPLEXER:
   - CBOR-kodierte Messages über NNG
   - REQ/REP Pattern für Zuverlässigkeit
   - Single TCP Port für alle Kameras

4. RUST OPTIMIZATION:
   - FrameBuffer für effizientes Buffer-Management
   - FrameMetadata für Timing-Informationen
   - Möglichkeit für GPU-Integration (Future)

5. CONFIGURATION:
   - TOML-basiert
   - Pydantic-validiert
   - Per-Vendor Settings
